## Superseded designs retained for history

| Earlier design                                                                                            | Current decision                                                                                                                                                  | Earlier detail                                                                                                                        |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| A boiler zone exists only as a shared Climate Controller; there is no Zone entity                         | Zones are explicit scheduling locations and may contain zero or more rooms and climate controllers                                                                | [Hierarchy](./docs/ORIGINAL_SPEC.md#3-unified-entity-hierarchy), [boiler zones](./docs/ORIGINAL_SPEC.md#4-mvp-boiler-zone-semantics)  |
| Room-to-controller links alone describe the topology                                                      | A room may belong to zero or one zone; climate controllers attach to a zone or a room and each references a Plant                                                 | [Room](./docs/ORIGINAL_SPEC.md#32-room), [Climate Controller](./docs/ORIGINAL_SPEC.md#33-climate-controller)                          |
| Schedule assignments and base/override selections are per room                                            | Each schedule spans the installation; one main and one override slot select the whole-house plan                                                                  | [Schedule](./docs/ORIGINAL_SPEC.md#36-schedule)                                                                                       |
| A schedule period is a comfort band and controller choice is automatic                                    | An MVP block selects one attached `climate.*` entity and its available climate controls; automatic source choice is deferred                                      | [Schedule](./docs/ORIGINAL_SPEC.md#36-schedule), [demand and source selection](./docs/ORIGINAL_SPEC.md#5-demand-and-source-selection) |
| Room temperature sensors are required to make scheduled demand                                            | The selected climate entity's own thermostat regulates its scheduled mode and target in the MVP                                                                   | [Room](./docs/ORIGINAL_SPEC.md#32-room), [prediction](./docs/ORIGINAL_SPEC.md#7-prediction-and-solar-exposure)                        |
| A room block may inhibit a shared controller only through general source conflicts                        | Any active room block suppresses all climate entities attached to its zone under automatic control                                                                | [Schedule](./docs/ORIGINAL_SPEC.md#36-schedule), [source selection](./docs/ORIGINAL_SPEC.md#5-demand-and-source-selection)            |
| Manual controllers are never commanded and each controller chooses among earlier manual-override policies | Conflicting zone/room manual on-actions turn off the other side; the latest wins; default expiry is the next block boundary, with an optional per-entity end time | [Control ownership](./docs/ORIGINAL_SPEC.md#6-control-ownership-and-manual-operation)                                                 |
| Home Assistant uses engine operations to choose each room's schedule; MQTT had no demonstrated role       | Home Assistant MQTT select entities choose the installation-wide slots, using broker settings configured in Aether                                                | [Schedule](./docs/ORIGINAL_SPEC.md#36-schedule), [architecture](./docs/ORIGINAL_SPEC.md#10-system-architecture-and-technology)        |

Before promoting a deferred idea, update [SPEC.md](./SPEC.md) through the repository's approval process. Preserve this index and the archived text so the reason for each change remains visible.
